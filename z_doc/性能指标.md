### 帧率

- 设置中可以打开

- 代码检测

  ```kotlin
  class FPSMonitor {
      private var frameCount = 0
      private var startTime = 0L
      private var lastFPS = 0f
  
      private val frameCallback = object : Choreographer.FrameCallback {
          override fun doFrame(frameTimeNanos: Long) {
              if (startTime == 0L) {
                  startTime = frameTimeNanos
              }
              frameCount++
  
              val duration = (frameTimeNanos - startTime) / 1_000_000_000f
              if (duration >= 1f) {
                  lastFPS = frameCount / duration
                  Log.d("FPSMonitor", "Current FPS: $lastFPS")
                  frameCount = 0
                  startTime = frameTimeNanos
              }
              Choreographer.getInstance().postFrameCallback(this)
          }
      }
  
      fun start() {
          Choreographer.getInstance().postFrameCallback(frameCallback)
      }
  
      fun stop() {
          Choreographer.getInstance().removeFrameCallback(frameCallback)
      }
  
      fun getLastFPS(): Float = lastFPS
  }
  
  ```

### 内存

**Android 应用在运行时完全可以打印当前的内存占用情况**，包括：

> - 应用进程占用的 **Java 内存（heap）**
> - **Native 层内存**
> - **总 PSS（Proportional Set Size）**
> - 分配限制（如 max heap）



- 代码检测

```kotlin
val memoryInfo = Debug.MemoryInfo()
Debug.getMemoryInfo(memoryInfo)

Log.d("Memory", """
    Total Pss        = ${memoryInfo.totalPss} KB
    Dalvik Pss       = ${memoryInfo.dalvikPss} KB
    Native Pss       = ${memoryInfo.nativePss} KB
    Other Pss        = ${memoryInfo.otherPss} KB
""".trimIndent())

📌 totalPss：应用占用的所有内存（包括共享库等）

📌 nativePss：C/C++ 层使用的内存

📌 dalvikPss：Java/Kotlin 层堆使用内存
```

adb shell dumpsys meminfo com.walisport.app

# 卡顿检测

原理：检测帧与帧绘制间隔时间，超过一定阈值，认为是卡顿

（1）主流框架
BlockCanary：利用Looper消息和Choreographer
    （1）Looper.getMainLooper().setMessageLogging()
    （2）Choreographer.FrameCallback.doFrame()
Matrix Trace：字节码插桩，打点主线程方法执行点，生成完整调用链+CPU时间

（2）帧率
60 fps: 每帧的时间不应超过 16 毫秒
90 fps: 减少至 11 毫秒
120 fps: 减少至 8 毫秒

（3）冻结帧和慢帧
在应用启动或切换界面时，初始帧的绘制时间超过 16 毫秒属于正常情况，这是因为您的应用必须扩充视图，并从零开始执行初始绘制。因此，Android 将冻结的帧与呈现速度缓慢情况分开跟踪。您应用中的任何帧的呈现时间都不应超过 700ms。

冻结的帧:是指呈现时间超过 700ms 的界面帧。这意味着您的应用在帧呈现过程中几乎有一秒钟的时间卡住不动，对用户输入无响应。
慢帧:16 毫秒到 700 毫秒
呈现速度缓慢的问题难以重现，但您可以从消除 700 毫秒的冻结帧入手。

（4）3种启动方式
Android Vitals 认为您的应用存在以下启动时间过长的情况：

冷启动用了 5 秒或更长时间。
温启动用了 2 秒或更长时间。
热启动用了 1.5 秒或更长时间。

总结：重点处理冻结的帧
